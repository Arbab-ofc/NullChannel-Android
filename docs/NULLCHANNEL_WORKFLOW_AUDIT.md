## Hosted flow detail

The actual browser harness is `scripts/verify-browser-workflows.mjs`. It runs against local React/Vite and Express/Socket.IO, checks `/api/health/db`, and uses the existing Supabase Auth/database. It creates three isolated accounts, with the third used for self-service deletion, plus a guest context. Account A and B remain independent after C deletion. The script does not log credentials or tokens.

The hosted registered harness is `server/src/scripts/verify-registered-upgrade.ts`. The latest complete run passed confirmed fixture login/profile, friendship, multi-tab presence/invisible filtering, direct registered socket message and Burn receipt with destruction/friendship survival, public discovery/join/termination, group invite token, duplicate poll prevention, moderation and cascade, a two-user match proposal, rejected reveal, Ghost-to-Friend, and an actual 60-second hosted timeout with queue cleanup. It created three disposable Auth fixtures and removed them in `finally`. A follow-up adds Socket.IO messaging in the matched room and mutual identity reveal.

The ImageKit probe is `server/src/scripts/verify-private-media.ts`. It creates and deletes only its own provider file. Provider metadata lookup succeeded, while each tested delivery route returned 404; the external media condition remains open.

## Fixes during audit

- Removed the broad account-wide request limiter that caused ordinary authenticated account reads to return 429 under three concurrent browser users. Login/signup/recovery/reset/refresh/password-change/delete retain explicit narrower limits.
- Moved authenticated presence disconnect listener setup ahead of asynchronous Socket.IO joins and database operations to close the disconnect-before-listener race.
- Allowed explicit presence status changes through the heartbeat throttle. Hosted online/away/invisible/offline assertions passed; focused presence suite reports 8 passing tests.
- Silenced an expected disconnect race when account deletion removes the profile before presence broadcasting finishes. The regression test confirms cleanup remains successful without a false error log.
- Corrected a TypeScript-only ImageKit audit script property assertion. This did not change runtime provider behavior.
- Converted provider delivery errors into a safe `MEDIA_DELIVERY_UNAVAILABLE` 503 instead of leaking a raw Axios failure as HTTP 500. Direct provider tests still return 404, so successful delivery remains blocked on the existing ImageKit delivery configuration.

### ImageKit account action required

Open the ImageKit dashboard’s [URL Endpoints](https://imagekit.io/dashboard/url-endpoints). Edit the endpoint whose exact URL is configured as `IMAGEKIT_URL_ENDPOINT`. Confirm it belongs to the same ImageKit account as `IMAGEKIT_PUBLIC_KEY` and `IMAGEKIT_PRIVATE_KEY`, and that its origin preference serves files from that account’s ImageKit Media Library. Save the endpoint, then rerun `npx tsx server/src/scripts/verify-private-media.ts` and the real browser media workflow. Delivery is not verified until the signed request returns the uploaded bytes successfully. ImageKit documents the `ik-error` diagnostic and origin behavior in its [404 troubleshooting documentation](https://imagekit.io/docs/integration/connect-external-storage).

### Supabase Auth action required

In Supabase Dashboard → Authentication → URL Configuration, allow the configured client’s `/login` confirmation redirect and `/reset-password` recovery redirect. In Authentication → SMTP Settings, configure a deliverable SMTP provider. Review the confirmation and password recovery templates so their action links preserve Supabase’s configured redirect URL. Then use a mailbox controlled by the test operator to complete confirmation and password recovery end to end. The code passes `${CLIENT_URL}/login` for signup confirmation and `${CLIENT_URL}/reset-password` for recovery; the dashboard allowlist and templates could not be verified without a Supabase Management API token.

The responsive screenshot script creates a disposable confirmed Supabase Auth fixture and a temporary guest room, then removes the Auth fixture. The chat-only screenshot run creates and terminates its own room. All test media and database records were scoped to their audit fixtures.
